Email Integration & Security Architecture
1
System Purpose & Usage

The DPR System relies on this central email account for automated outgoing communications (such as Quotations, DPR reports, and Supplier Purchase Orders) and incoming email synchronization (IMAP inbox sync and AI Classification).

2
Credential Decoupling (Security Fix)

Previously, sensitive mail credentials were hardcoded directly within source code files and version control repositories. This presented a severe security risk on Git and Cloud hosts. Credentials are now completely removed from the code and managed dynamically by administrators through this interface.

3
Enterprise AES-256 Encryption

Passwords entered into this form are never stored as plain text. The system automatically encrypts the password at rest using symmetric AES-256 Fernet cryptography before persisting to the database. Even direct database inspections will only reveal encrypted ciphertext.

4
Seamless End-User Operations

Non-administrative team members continue using standard operations—such as clicking "Sync Email" or sending DPR notifications—without any change or manual password prompts. The backend loads and authenticates connections automatically in memory.
